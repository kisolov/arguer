# arguer

Telegram-бот, который помогает выигрывать споры в переписке. Пользователь пересылает боту сообщения (текст или голосовые), выбирает, чью сторону защищать, и LLM формирует список аргументов в пользу «подзащитного» и против оппонента. Использование платное: внутренняя валюта ✨ списывается за запрос и пополняется через ЮKassa.

> Проект учебно-портфолийный. Системный промпт намеренно однобокий: бот защищает выбранную сторону, а не ищет истину.

## Как это работает

1. Пользователь пересылает сообщения спора. Голосовые расшифровываются через Yandex SpeechKit (файлы временно кладутся в S3-бакет).
2. `/go` запускает разбор. Если подзащитный не выбран, бот показывает кнопки выбора.
3. Реплики размечаются («клиент — ЗАЩИТИТЬ», «оппонент — ОПРОВЕРГНУТЬ») и отправляются в LLM через GenAPI.
4. Стоимость = базовая ставка + символы контекста + секунды голоса (`CostCalculator`), списывается `BillingService`.
5. Пока идёт обработка, ввод пользователя блокируется состоянием FSM.

Команды: `/start`, `/go`, `/clear`, `/ctx`, `/bal`.

## Архитектура

Слоистая структура с зависимостями, направленными внутрь:

```
src/
  domain/          модели, порты (интерфейсы), доменные сервисы (спор, биллинг, стоимость)
  application/uc/  юзкейсы: по одному на действие пользователя
  infrastructure/  адаптеры: aiogram, Pony ORM (MySQL), Redis, Yandex Cloud, ЮKassa, GenAPI, APScheduler
  presentation/    aiogram-роуты и middleware (регистрация, сессия, обработка ошибок)
di.py              сборка зависимостей (dependency-injector)
config.py          настройки на pydantic-settings, секреты как SecretStr
```

Стек: Python 3.12, aiogram 3, Pony ORM + MySQL 8, Redis, dependency-injector, Yandex Cloud (SpeechKit, Object Storage), ЮKassa, Docker Compose.

## Запуск

```bash
cp .env.example .env                    # заполнить токены и ключи
cp yc_config.example.yaml yc_config.yaml  # ключ сервисного аккаунта Yandex Cloud
make up                                 # mysql + redis + phpmyadmin + бот
make log c=telegram-bot
```

`.env` и `yc_config.yaml` в git не попадают.

## Тесты

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
pytest tests
```

Внешние сервисы в тестах заменены моками (`tests/mocks`), сценарии лежат в `tests/cases`.
